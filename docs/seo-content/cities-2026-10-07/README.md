# Городские посадочные — второй этап

**Статус: тексты и изменения вывода подготовлены, база не обновлена.** Повторный вход в HostCMS не завершён. Production не менялся. Не считать эти тексты опубликованными.

Используется существующий магазин 6: элементы 240 (Красногорск), 233 (Зеленоград), 236 (Истра), 238 (Химки), 242 (Солнечногорск). Пути и предлагаемые метаданные — в `manifest.json`. Поле `description` сохраняется коротким; новые блоки предназначены для существующего поля `text`. Названия, цены, изображения и дополнительные свойства не менять.

В резервной копии у этих записей уже есть старые тексты, но активная часть XSL 56 их не выводит. Подготовленный вывод `text` ограничен магазином 6 и пятью указанными элементами, чтобы не открыть непроверенные старые тексты других городов. Блок использует существующее оформление `data-seo-landing` и доступен в серверном HTML.

Перед публикацией: получить свежий экспорт выбранных записей; сравнить ID, магазин и текущий путь с manifest; сохранить исходные `text`, `seo_title`, `seo_description`; заменить поля через штатную форму HostCMS; после этого переносить изменение XSL. Значения из старого бэкапа не являются основанием для массовой записи.

`tools/seo/generate-city-content-sql.py` создаёт SQL применения и отката только из свежего экспорта выбранных строк. Набор ID и путей фиксирован manifest. UPDATE проверяет старые значения всех изменяемых полей; по умолчанию транзакция заканчивается ROLLBACK. Скрипт не подключается к базе и не выполняет SQL.

Пример подготовки после получения актуального JSON экспорта:

```sh
python3 tools/seo/generate-city-content-sql.py \
  --export /absolute/path/current-shop6-rows.json \
  --output /absolute/path/reviewed-city-content
```

Формат экспорта: массив объектов с `id`, `shop_id`, `path`, `deleted`, `text`, `seo_title`, `seo_description`. NULL сохранять как JSON null. ID и пути берутся из существующих записей, не создавать новые элементы.
