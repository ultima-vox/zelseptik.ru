# План работ по ТЗ ЗЕЛСЕПТИК 2.0

Этот план применяет [полное ТЗ](ZELSEPTIK_2_0_TZ.md) к основному репозиторию. Пункты являются задачами, а не утверждением, что соответствующая функция уже работает. Каждый этап — отдельный проверяемый diff без массового переписывания сайта.

## 0. Сверить платформу и исходники

1. Получить read-only доступ к установленной версии HostCMS и официальной документации именно для неё; записать версии, редакцию, PHP и СУБД.
2. Снять свежие SHA-256 шаблонов, XSL, CSS/JS и сравнить с `codex/hostcms-baseline-homepage`. Сохранить diff и резервную копию перед изменениями.
3. Заполнить [HOSTCMS_ARCHITECTURE.md](HOSTCMS_ARCHITECTURE.md) реальными ID, полями, XML и маршрутом форм. Проверить, какие из старых компонентов дизайн-системы реально используются.
4. Проверить сборку `npm run build`, `npm run lint`, XSL и доступность локальных инструментов. Не публиковать файлы из `hostcmsfiles/documents/` напрямую.

## 1. Аудит и карта миграции

1. Снять crawl production и dev: все индексируемые URL, ответы, title, description, H1, canonical, robots, sitemap, редиректы и внутренние ссылки.
2. Проверить карточки, свойства и цены товаров; формы, обработку лидов, мобильное меню, калькулятор, фильтры и сравнение. Зафиксировать реальные проблемы и влияние на заявки.
3. Создать `URL_MIGRATION.md` с `KEEP`, `UPDATE`, `301`, `410`, `MERGE` для каждого изменяемого URL. Не принимать решение о массовых редиректах до полной карты.
4. Снять исходные показатели заявок и конверсии по каналам, если доступна аналитика; иначе пометить baseline как неизвестный.

## 2. Устранить ошибки данных и критические дефекты

Приоритет: неверные характеристики и цены, неработающие формы/телефон/мессенджер, утрата заявок, открытая индексация dev, неверный email, сломанные ссылки, дубли и ошибочные геотексты. Каждое исправление сопровождается проверкой на dev и адресным rollback.

## 3. UI и три конверсионных пути

1. Сверить текущие токены и классы с дизайн-системой; унифицировать typography, buttons, cards, forms, focus/ошибки, header/footer. Не подключать второй конкурирующий CSS-слой без удаления дублирования.
2. Главная: ясное предложение и три пути (подбор/монтаж, обслуживание, ремонт), быстрый выбор, реальные доказательства, контекстные CTA.
3. Подбор: короткие вопросы о доме и участке, объяснимые 2–3 рекомендации только по валидированным свойствам; неопределённость передаётся инженеру.
4. Каталог и товар: сохранить серверную логику HostCMS, фильтрацию и URL; показать пригодность, ограничения, цену оборудования и состав монтажа, сравнение и заявку.
5. Монтаж, обслуживание и ремонт: отдельные сценарии, реальные цены/условия, безопасные проверки, форма по контексту.
6. Кейсы, геостраницы и статьи: только реальные данные и уникальная польза; не генерировать сотни шаблонных страниц.

## 4. SEO, измерение и приёмка

Проверить карту URL/редиректы, canonical, sitemap, robots, структурированные данные, метаданные и перелинковку. Подключить согласованные события и UTM к существующему маршруту заявок. Затем проверить ширины 320–1920 px, поддерживаемые браузеры, клавиатуру, формы, фильтры, подбор, сравнение, реальные лиды, консоль и mobile Core Web Vitals. Отклонения от целевых LCP ≤ 2.5 s, INP ≤ 200 ms, CLS ≤ 0.1 документировать с причиной и условиями измерения.

## Граница текущего изменения

Сейчас собраны ТЗ и карта источников. Код production, dev и данные HostCMS не изменялись. Первый кодовый этап начинается после сверки источника истины на сервере и официальной документации версии HostCMS.
