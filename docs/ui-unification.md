# Унификация UI

## Утверждённые эталоны

`/`, `/contacts/`, `/about/`, `/promotion/`, `/dostavka/`, `/septiki/`.
Задача — перенести их визуальные правила на остальные страницы, сохранив данные CMS.
Редизайн утверждённых страниц не входит в этот этап.

Общая последовательность CSS подтверждена на всех шести страницах:
`assets/css/app.min.css`, `assets/css/runtime.min.css`, CSS макета 1, CSS дочернего макета.
Полные подключения сохранены в `production-assets.json`.

## Очерёдность

1. Проверить текущие классы и каскад на одном представителе каждого типа страницы.
2. Привести списки и подробные страницы услуг/монтажа/обслуживания/ремонта к общей схеме.
3. Привести страницы брендов и товаров; использовать магазин и текущие свойства.
4. Привести кессоны, погреба и региональные страницы.
5. Привести статьи, политику конфиденциальности, карту сайта и страницы ошибок.
6. Проверить повторно утверждённые страницы после изменения общих компонентов.

Общие элементы: контейнер, хлебные крошки, первый экран, заголовки секций,
карточки, таблицы, изображения, процесс, FAQ, CTA, формы, шапка и подвал.
Тип страницы определяет состав контента, но не отдельную палитру или набор кнопок.

## Приёмка

- Сравнение на ширинах 375, 768, 1024 и 1440 px: нет горизонтального скролла,
  перекрытий, обрезанных заголовков или недоступных элементов.
- Единые токены цвета, типографика, радиусы, отступы, контейнеры и состояния кнопок.
- Формы сохраняют модель/услугу, валидацию, результат отправки и существующий обработчик.
- Сохраняются фильтры, ссылки на модификации, пагинация и отображение данных CMS.
- Новые дублирующие компоненты и стили не добавляются без обоснования.
- Проверка в браузере на тестовой HostCMS; наличие файлов в Git само по себе не подтверждает внедрение.

Текущий этап подготовил исходники и карту связей. UI страниц ещё не изменён.
