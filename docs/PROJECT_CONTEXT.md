# ЗЕЛСЕПТИК 2.0 — единый контекст проекта

## Цель и границы

Модернизировать действующий `zelseptik.ru` на HostCMS для роста числа квалифицированных заявок на подбор, продажу, монтаж, обслуживание и ремонт автономной канализации. Сохранить домен, полезные URL, данные каталога и SEO-ценность. Редизайн возможен поэтапно и должен опираться на проверенную архитектуру сайта.

Полное пользовательское ТЗ: [ZELSEPTIK_2_0_TZ.md](ZELSEPTIK_2_0_TZ.md). При расхождении краткого обзора с ним действует полное ТЗ. Технические предположения из старых репозиториев не являются подтверждением поведения установленной версии HostCMS.

## Основной репозиторий

`ultima-vox/zelseptik.ru` выбран как единственный репозиторий для дальнейших изменений сайта. Ветка `codex/hostcms-baseline-homepage` содержит импортированный снимок HostCMS и исходники CSS/JS; текущая `main` пока содержит только frontend workspace. Настоящая ветка создана поверх HostCMS baseline. Пользователь сообщил 28.09.2026, что файлы с dev уже перенесены на production. Перенос baseline в `main` возможен после сверки снимка с production и dev и ревью. Сам факт переноса не подтверждает совпадение файлов и данных БД с Git.

Репозиторий `Full-Design-System` служит историческим источником дизайн-системы и отдельных шаблонов, а пустой `zelseptik` не используется как источник кода. Правила сверки — в [SOURCE_INVENTORY.md](SOURCE_INVENTORY.md).

## Три пользовательских сценария

1. Новый клиент: условия дома и участка → 2–3 подходящие модели с объяснением → стоимость оборудования и монтажа → похожая выполненная работа → заявка.
2. Клиент с выбранной моделью: каталог → бренд → модель → характеристики → монтаж → заявка.
3. Действующий клиент: обслуживание или ремонт → проблема, порядок работ и цена → вызов мастера.

Подбор и расчёт должны использовать проверенные свойства товаров и тарифы. Если исходных данных нет, показывать ограничения и предлагать расчёт инженером, не выдавая вымышленные рекомендации или цены.

## Неподвижные условия реализации

- HostCMS остаётся CMS, каталогом и источником редактируемых данных. Не создавать отдельный frontend, базу товаров или дублирующую административную систему.
- До правок XSL, форм, фильтров и данных проверить установленную версию, официальный механизм и реальный XML/код. Не изменять ядро HostCMS.
- Не хардкодить цены, товары, характеристики, контакты, города и другие данные редактора в разметке.
- Сохранять индексируемые URL либо готовить адресную карту 301/410/merge. Не запускать массовую генерацию геостраниц.
- Не придумывать отзывы, сроки, скидки, гарантии, характеристики и результаты работ.
- Изменять по одному работающему этапу; перед деплоем сверять серверный baseline и делать резервную копию. Порядок указан в [hostcms-deployment.md](hostcms-deployment.md).

## Где лежит работа

| Область | Путь в этой ветке | Статус |
| --- | --- | --- |
| Серверный CSS на дату экспорта с dev | `core/*.css` | снимок; сверить с production и dev |
| Новая дизайн-система | `src/scss/`, `docs/` | исходники и правила; не считать автоматически подключёнными к dev |
| Основной шаблон HostCMS | `templates/template1/template.htm` | снимок; сверить с dev |
| Главная | `templates/template2/template.htm`, `hostcmsfiles/documents/` | шаблон и снимки документов из БД |
| Каталог и карточка | `hostcmsfiles/xsl/55.xsl`, `56.xsl` и остальные XSL | сверять ID, XML и текущие файлы |
| Frontend JS | `script.js`, `templates/template1/script.js`, `src/js/` | действующий и проектируемый слои различаются |
| Сборка и перенос | `package.json`, `scripts/`, `docs/hostcms-deployment.md` | проверить build/lint и контракт путей |
