## Что в прежнем репозитории не соответствует рабочей основе

1. Старый README называет workspace готовым к продакшену и предлагает `/dist/`.
   Действующий сайт подключает `/assets/` и CSS/JS макетов HostCMS.
2. `src/js/modules/calculator.js` и `catalog.js` — заглушки, тогда как на сайте
   имеются реализации. Другие заглушки и черновые SCSS также не подтверждены как рабочие.
3. Старая npm-сборка компилирует CSS, но README обещает `dist/js/app.js`,
   для которого в package.json нет сборки.
4. Параллельные папки компонентов, design-system, legacy и варианты HTML/CSS
   создают несколько конкурирующих источников визуальных правил.
5. Старая документация внутренних страниц прямо сообщает об отсутствии проверки DOM
   и предлагает алиасы без подтверждения фактической разметки.

Архивирование означает исключение из текущей рабочей основы, а не утверждение,
что каждая архивная идея бесполезна. История и содержимое сохранены.

## Сохранённые ограничения

- Наличие `assets/css/core/` на сервере не доказывает, что app.min.css собран из них.
  Подключённые app.min.css, runtime.min.css и стили макетов — подтверждённый эталон.
- Архивная SCSS-сборка не воспроизведена и не используется для перезаписи текущего CSS.
- Статический анализ не подтверждает все условные вызовы и переопределения CMS.
  Не разрешённое имя XSL записано в inventory.json.
- Макеты, XSL и PHP перенесены как исходный снимок; исправление их логики не входило в эту очистку.
- PHP-интерпретатор и установленная HostCMS в рабочем окружении отсутствуют:
  серверное выполнение и отправка форм здесь не проверены.
- Полный бекап, SQL, ядро CMS, конфигурация, заказы и пользователи не включены в Git.
- UI страниц и продакшен не изменены. Отдельный план унификации находится в ui-unification.md.
