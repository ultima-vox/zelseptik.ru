Создай сайт который станет полноценным коммерческим инструментом компании «ЗелСептик» и будет приводить больше квалифицированных заявок на подбор, продажу, монтаж, обслуживание и ремонт автономной канализации.

Сайт НЕ требуется создавать с нуля как отдельный новый проект. Необходимо провести глубокую модернизацию существующего сайта https://zelseptik.ru/ с сохранением домена, накопленной SEO-ценности, существующих полезных URL, товарного каталога, данных, структуры HostCMS и уже реализованных удачных компонентов.

Главная цель проекта — увеличить количество квалифицированных лидов и сделать сайт понятным человеку, который не является специалистом по септикам.

Работай как senior web developer, UX/UI designer, SEO specialist и CRO specialist, но все технические решения принимай только в рамках реальной архитектуры HostCMS.

# 1. КРИТИЧЕСКОЕ АРХИТЕКТУРНОЕ ОГРАНИЧЕНИЕ

Сайт работает на HostCMS.

HostCMS должна остаться основной CMS, системой управления контентом, каталогом, страницами и данными.

Нельзя проектировать сайт так, будто HostCMS является только backend API.

Не создавать без объективной необходимости:

- отдельный frontend;
- SPA;
- React/Vue-приложение;
- headless-архитектуру;
- собственный router;
- собственную CMS;
- собственную административную панель;
- отдельную базу товаров;
- собственный ORM;
- отдельный backend;
- GraphQL;
- собственный REST API.

Если штатные механизмы HostCMS решают задачу — использовать их.

Главный принцип:

**максимум возможностей HostCMS, минимум пользовательского кода.**

# 7. XSL

Перед изменением XSL изучить XML, который реально формирует HostCMS.

Не предполагать структуру XML.

Перед использованием:

```text
/property
/item
/shop_item
/group
```

или любого другого узла убедиться, что он реально присутствует.

Не создавать XPath по предположению.

Не делать сложную бизнес-логику внутри XSL, если она должна находиться на уровне данных или штатной логики CMS.

Повторяющиеся блоки выносить в переиспользуемые templates.

# 74. ОСНОВНОЙ ПРИНЦИП РЕАЛИЗАЦИИ

Не пытайся сделать сайт технологически сложнее, чем требуется бизнесу.

Главная задача — сделать существующий сайт:

- понятнее;
- быстрее;
- убедительнее;
- технически чище;
- удобнее;
- лучше индексируемым;
- лучше конвертирующим трафик в клиентов.

Любое техническое решение должно отвечать четырём требованиям:

1. Подтверждено официальной документацией HostCMS или фактическим рабочим кодом установленной версии.
2. Не требует изменения ядра HostCMS.
3. Использует минимум нового пользовательского кода.
4. Даёт измеримую пользу сайту или пользователю.

Если пользы нет — не реализовывать.

# 75. ИТОГОВЫЙ ПРОДУКТОВЫЙ СЦЕНАРИЙ

После завершения модернизации пользователь должен иметь возможность:

```text
зайти на сайт
↓
сразу понять, чем занимается компания
↓
указать условия дома и участка
↓
получить 2–3 подходящие станции
↓
понять разницу между ними
↓
увидеть ориентировочную цену оборудования
↓
увидеть стоимость монтажа
↓
увидеть реальный похожий объект
↓
понять, почему это решение подходит
↓
оставить заявку
```

При этом опытный пользователь должен иметь возможность напрямую:

```text
Каталог
→ бренд
→ модель
→ характеристики
→ монтаж
→ заявка
```

А существующий клиент:

```text
Обслуживание / ремонт
→ проблема
→ стоимость
→ вызов мастера
```

Именно эти три сценария являются основной логикой нового ZelSeptik 2.0.
