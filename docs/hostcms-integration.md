# Интеграция с существующей HostCMS

Окружение по скриншоту пользователя: HostCMS 7.1.6 «Старт», PHP 7.2.34,
MySQL 8.0.45-36, память 128M. Не подменять эти сведения параметрами другого проекта.

## Обязательные правила

- Использовать только официальную документацию HostCMS и сверять доступность методов с установленной версией.
- Сохранять существующие магазины, информационные системы, группы, элементы, свойства и их ID.
- Не переносить динамические данные в статические массивы ради оформления.
- Сохранять URL, обработчики форм, цены, фильтры, пагинацию и связи модификаций.
- Менять представление через существующие макеты и XSL; не создавать параллельную CMS.
- Повторно использовать текущие CSS-классы, токены и JS-хуки. Новые стили — только при отсутствии подходящего решения.
- HTML5/CSS/JS, без React, Tailwind и Bootstrap; адаптация от мобильного экрана.
- Не публиковать SQL, полный бекап, секреты, пользователей и заказы в Git.

В текущей схеме родительский макет 1 задаёт общую оболочку. Стили и скрипты дочерних
макетов подключаются после родительских; этот порядок важен для каскада.
Имена XSL из параметров структуры и прямых вызовов записаны в `hostcms/inventory.json`.
Файлы XSL используют существующие идентификаторы; зависимости `import://ID`
не переписывать в вымышленные файловые пути.

## Границы подтверждения

Связи восстановлены из структуры БД и статических вызовов в бекапе. В них могут
быть закомментированные вызовы и неиспользуемые значения по умолчанию.
Переопределения через свойства и фактический выбор макета для элемента требуют
проверки в CMS. Макеты 10/11/14 сохранены как кандидаты для подробных страниц,
их использование не объявляется подтверждённым для каждого URL.

В экспорт попал вызов `МагазинГруппыТоваровНаГлавнойСайт2`, не разрешённый в активных
записях XSL дампа. Это не основание удалять код: требуется проверить источник вызова.

Документы экспортированы из `documents.text`; таблица `document_versions` в дампе
пуста. Пустой документ 10 оставлен как существующая запись. Автоматических SQL-обновлений нет.

Перед внедрением: резервная копия, проверка конкретного шаблона на тестовой копии,
затем перенос только изменённых файлов/записей и проверка затронутых страниц.
